Three bits · two checks · a microscope on b2

What BP and gradient descent keep, beat by beat

Both columns run on the same Tanner graph and the same channel LLRs. Check A joins bits b1 and b2, and check B joins b2 and b3. The channel gives P(bi = 1 | yi) = 0.1, 0.6 and 0.9, so the LLRs Li = ln[P(bi = 1 | yi) / P(bi = 0 | yi)] are −2.197, +0.405 and +2.197. In this page’s variable-then-check flooding schedule, the iteration boundary is placed after the check update: BP therefore retains the latest check-to-variable U messages at that boundary. It recomputes variable-to-check Q messages from those U values and the channel LLRs, then uses the current Q values in the check update. A check-first implementation can place its iteration boundary elsewhere and carry Q into the next check update. Gradient descent keeps one number per bit, and its partial-derivative arrows last only until the step.

The two columns share H and L, not an objective. BP computes posterior LLRs, and gradient descent lowers Jp(x) = (1 − x1x2)2 + (1 − x2x3)2. Within an iteration the edges are shown one after another, but BP forms all four variable-to-check messages from the stored check-to-variable messages before any check replies, and every gradient term uses the same x. A beat is a step of the animation, not a unit of work; equal beats do not mean equal arithmetic, stored state or complexity. This is one example on one cycle-free graph, and it does not measure decoding performance. Each letter belongs to one method: Q, U and Λ are BP’s; x, r, g, Jp and η are gradient descent’s. Both read L, and both report a hard-decision estimate b̂.

Space plays or pauses, the arrow keys step and Home restarts. Every number is computed in this page from P(bi = 1 | yi) = (0.1, 0.6, 0.9) and η = 0.25, and is rounded to three decimals for display; sums use the unrounded values. A link can open at a beat, for example #beat12.
