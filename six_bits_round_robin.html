BP, Projected GD, and ADMM, Taking Turns

Each press of Next reveals one stage of one method, in the order BP → GD → ADMM → BP → … . A stage is one check’s calculation or the bits’ update, and the method’s worksheet shows each expression while it is animated. Within an iteration, both checks use the same frozen input state: the c0 then c1 order is a presentation order, not a sequential recomputation. The example is the six-bit one: L = (−0.38, +0.48, +0.14, +4.78, +2.85, +1.10), c0 joins bits 1, 2, 5, c1 joins bits 0, 3, 4, and the sent word is 010111. Each method runs two iterations.

Symbols, and what the turns do not claim

BP owns L, Q, t, U, B; GD owns x, x̃, r, g, η; ADMM owns p, b, z, u, ρ, Sc. All three use the checks c0, c1 and the matrix H; b̂ denotes each method's own hard-decision estimate. ADMM’s evidence is written p here because c names the checks, and GD’s gradient step is written x̃ so that z stays ADMM’s.

The controlled quantities shared across the three methods are the parity-check matrix H, the vector of channel LLRs L, and the reference sent word. GD starts from x(0) = tanh(L/2), and ADMM uses p = σ(L). They share the display turn order, not one objective. BP computes LLR messages; GD lowers Jp = Σc(1 + Πj∈N(c)xj)² with η = 0.25; ADMM minimizes ½‖b − p‖² with each check’s bits kept in the parity polytope PP3, with ρ = 1, as in the three-symbol page. Only BP’s Q and U are messages. Each GD quantity gc,i is the partial derivative of Jc with respect to xi; the check-associated partial derivatives are summed to form ∂Jp/∂xi and then discarded after the step. ADMM’s zc and uc persist between iterations. Equal reveal time is not a claim of equal arithmetic, state or computational cost.

These two checks do not share a bit. The page therefore isolates each local calculation, but it does not exercise BP aggregation from multiple neighboring checks or ADMM consensus between overlapping local replicas. It is a mechanism demonstration, not evidence that one decoder has better error-rate performance.
